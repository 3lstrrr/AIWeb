## 第 1 章 项目概述

**写作要点**

1. **一句话定位**：面向大学生的课程知识库问答系统——上传课件即建库，回答带原文引用。
2. **问题背景**（三句话讲清痛点）：复习资料分散在几十份 PDF 中检索困难；通用大模型会编造老师没讲的内容；缺少自测手段。
3. **目标用户**：考前复习的本科生（主）、需要出随堂测的老师（次）。
4. **成果概览**：功能清单 + 主界面截图（见附录截图清单 #1）。
5. **核心主张**：*宁可拒答，也不编造*——精确模式下检索不到依据即返回固定拒答文案，不调用模型。

## 第 4 章 AI 技术方案（重点章节）

按「数据进 → 检索 → 生成 → 兜底」四段写：

### 4.1 文档预处理与分块

- 逐页抽取文本（`pdf-parse` 的 `pagerender` 回调逐页处理，避免整篇拼接丢失页码）；
- 按段落边界切块，**512 token / 64 重叠**，中文按 1.5 字符/token 估算；
- 难点与解法：分页哨兵必须用**多字符**（实测某些 PDF 正文自带 `\f` 与 `\u0002-\u001f` 控制字符，单字符分隔符会把 5 页算成 16 页）；重叠片段要用「重叠 + 新段」重新校验 token 预算，否则单块会超 512。

### 4.2 向量化

- 智谱 `embedding-3`，**显式 `dimensions: 1024`**（默认 2048，与 `vector(1024)` 不匹配会直接报错）；
- 32 条/批，失败按 1s/2s/4s 指数退避重试 3 次；维度不符属确定性错误，**不重试**、立即失败；
- 幂等：只处理 `embedding IS NULL` 的行，中断可续做。

### 4.3 检索策略（两段式）

- 第一段：`match_documents` 向量召回 **Top-8**（`doc_ids` 支持按文档过滤）；
- 第二段：`bge-reranker-large` 精排取 **Top-4**；
- **降级设计**：精排超时/报错/返回结构异常 → 保持向量顺序，返回 `reranked: false`，问答不受影响。

### 4.4 Prompt 工程

- 双模式规则（precise 只依据 context / explore 需标注「（资料依据）」「（模型补充）」）；
- 引用规则：句末 `[n]`，禁止越界编号；
- **拒答策略**：precise 模式检索为空时直接返回固定文案，不调模型（措辞稳定 + 省 token + 零编造）；
- `temperature 0.3`、`maxOutputTokens 2048`。

### 4.5 安全三道防线

1. 输入检测（注入正则 + 敏感短语词表）→ 命中即短路，不调模型；
2. 生成约束（precise 模式 + context 限制）；
3. 输出兜底（空回复 / 敏感词 / 超长 → 降级文案或截断）。

### 4.6 Agent 设计（Tool Calling）

- 工具 ①`retrieveForQuiz(topic)`：按主题检索原文片段；
- 工具 ②`generateQuiz(questions)`：提交结构化题目，**服务端校验数量/题型/引用是否来自已检索片段**，不合规抛错让模型自我修正（`stepCountIs(4)` 兜底，防死循环）；
- 价值：把「结构化输出」与「可溯源校验」放在工具入参上，而不是依赖模型自觉。

### 4.7 知识图谱抽取

- 取前 40 个切片、每片 400 字（总量 12k 字符）控制 prompt；
- 单次 `generateObject` 产出 `{ nodes ≤20, edges ≤30 }`，服务端二次清洗（去重、丢弃悬空边与自环）；
- 结果缓存 `documents.graph_json`，二次打开秒出。

## 第 7 章 创新点说明

建议只写 4–5 条，每条「做法 + 为什么优于常见方案 + 证据」：

1. **页码级引用闭环**：不是「给一段相关文字」，而是点角标 → PDF 翻页 → 原句高亮。证据：截图 #1；实现上靠「切片记录页码 + 文本层前缀匹配」。
2. **可控双模式 + 硬拒答**：精确模式检索为空时不调模型，拒答文案由常量保证一致 —— 把「不编造」从 prompt 承诺变成代码约束。
3. **Agent 出题带溯源校验**：`generateQuiz` 工具在服务端校验每条 citation 是否来自本次检索片段，不合规抛错让模型重试 —— 用工具协议约束幻觉，而不是靠 prompt 祈祷。
4. **全链路降级设计**：精排失败→向量顺序；rerank 超时→不影响问答；模型空输出→兜底文案；构建内存不足→swap + webpack 兜底。
5. **极低成本可复制**：全套免费/低价依赖（GLM 免费档 + Supabase 免费额 + 单台 2C 云主机），学生可独立复现。

## 第 8 章 总结与展望

- **收获**：RAG 工程中「检索质量」比「模型大小」更决定体验；评测与可观测（`/debug`）比调参更重要；降级路径要一开始就设计。
- **不足**：无用户体系与历史回填；扫描件不支持；注入检测是规则匹配；引用高亮依赖文本层质量。
- **展望**：混合检索（BM25 + 向量）、评测集与自动回归、多租户 + RLS、OCR 支持、错题本与学习画像。
